# 质量与发布

## 发布前最小检查

```bash
pnpm test
pnpm build
```

所有新增业务计算必须同时覆盖纯函数测试与组件交互测试。当前回归重点包括：账期边界、材料换算、BOM 版本、销售成本快照、退款/删除、库存回滚、月度分摊、现金与利润分层、定价明细、成本分析模拟与空状态。

## 移动端视觉回归

关键页面在 375、390、414 宽度检查：

| 区域 | 应检查的内容 |
|---|---|
| 首页 | 结果卡、状态/现金、趋势日期、商品贡献、异常、中心记一笔导航 |
| 商品 | 商品列表、单件成本、成本分析入口、更多操作 |
| 经营 | 现金层、成本分析层、利润桥、销售纠错 |
| 弹层 | 采购、销售、退款、删除、BOM、月度分摊的字段和固定操作区 |
| 成本分析 | 商品切换、公式、环图、异常、快照趋势、模拟、保本、建议和CTA |

检查时尤其注意：无横向滚动、无文字截断、44px以上触控区、固定导航不遮挡内容、现金不显示为利润、预计和已结转不混淆。

## 发布与回滚

项目通过受控检查点发布。每次功能完成后应：核对 `todo.md`、运行测试与构建、保存检查点、记录本次变更和验证范围。如发布后发现无法通过常规修复恢复的故障，应回退到最近稳定检查点；数据库迁移和用户数据需要单独谨慎处理。

## 已知工程提示

生产构建可能提示部分前端包较大。该提示不阻断构建，但后续可按页面或图表功能进行动态导入，以减少首次加载体积。测试环境中的图表容器尺寸告警不影响当前测试结果；若重构图表容器，应继续确保 JSDOM 与真实浏览器均可稳定渲染。
