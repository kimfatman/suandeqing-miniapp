# 系统架构

## 总体结构

```text
移动端 React 页面
   │
   ├── 本机账本状态（localStorage）──> 成本与销售计算引擎
   │                                   │
   │                                   └── 首页、商品、经营、定价、成本分析与报表
   │
   └── tRPC 客户端 ──> Express / tRPC 服务端 ──> MySQL/TiDB
                              │                     ├── 用户与 OAuth 会话
                              │                     ├── 云端账本备份
                              │                     └── 站内消息
                              └── Manus OAuth 与平台能力
```

## 前端职责

`Home.tsx` 是移动端工作台外壳，管理主导航、账本状态和各业务弹层。成本计算不依赖远端接口即可完成，保证小商家在本机账本中能快速录入与复算。页面通过 `ledgerStore.ts` 获取统一数据模型和纯函数计算结果，避免在 UI 内复制公式。

主要视图包括：首页经营驾驶舱、商品成本、商品绑定的成本分析、经营现金/利润层、个人设置、材料采购、销售记录、退款/删除、BOM、月度分摊与报表。

## 服务端职责

Express 负责应用入口与 Vite 开发桥接；tRPC 提供类型安全的 OAuth、云端备份和消息过程。数据库不用于取代本机账本的即时编辑，而用于账号关联、备份与消息记录。认证通过 Manus OAuth 完成，JWT 会话由服务端管理。

## 关键领域对象

| 对象 | 作用 |
|---|---|
| `LedgerData` | 本机账本根对象，包含商户资料、成本设置、材料、商品、现金流水与销售 |
| `LedgerProduct` | 商品售价、直接成本、完整成本、BOM、库存和版本信息 |
| `Material` | 采购/使用单位、换算、单位成本与采购原始数据 |
| `SalesRecord` | 销量、售价、业务日期、成本快照、退款与撤销状态 |
| `MonthlyIndirectCostPlan` | 本期固定费用、折旧、有效日期、分摊方法与商品依据 |
| `LedgerRecord` | 实际现金流水，区分手工、采购、销售与退款来源 |

## 数据流原则

商品的当前成本由材料、BOM、快速成本、月度分摊和资金成本组成；销售时将当时成本保存为快照。首页与经营分析使用两条并列但不混淆的路径：现金路径汇总已收和已付，利润路径汇总销售收入与冻结成本。商品成本分析的模拟是临时 UI 状态，绝不写入账本，除非用户在相应表单中明确保存。

## 可扩展方向

新增业务能力时，先定义领域数据和纯计算函数，再接入页面与入口。涉及账户、备份、消息或新表时，应扩展 tRPC 与 Drizzle；纯本机核算/展示能力优先保持在 `ledgerStore.ts` 与前端组件中，并用 Vitest 固化边界。
