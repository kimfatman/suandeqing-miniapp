# “算得清”全面易用性审计

**审计目标：** 在不牺牲成本核算准确性、销售快照和数据可追溯性的前提下，减少小商户的录入步骤、降低术语理解成本，并让用户始终知道“现在该做什么”。本次审计覆盖首次建账、日常收支、材料采购、商品成本、定价、销售结转、月度分摊、经营复盘、数据管理与消息提醒。

> **审计结论：** 产品的核算边界、历史快照、退款/删除保护和分摊解释已经较完整；当前主要问题不在“功能缺失”，而在于功能入口分散、同一任务需要跨多个弹层、预测成本与已发生现金容易在视觉上并列，以及高级字段过早出现。下一轮应从“继续加功能”转向“收敛为更少的任务入口”。

## 一、当前成熟度概览

| 维度 | 现状评估 | 主要观察 | 优先级 |
|---|---|---|---|
| 首次建账 | 良好 | 两步行业/店铺名称流程短，空账本边界明确 | P2 |
| 日常收支 | 可用但分流 | 普通收支、材料采购、商品销售分别进入不同弹层 | P0 |
| 商品成本 | 有两层能力 | “快速成本”合适，但进阶明细一次展示过多字段 | P1 |
| 定价 | 逻辑较透明 | 已展示成本来源；仍需澄清毛利率与加价率的区别 | P1 |
| 销售与纠错 | 核算安全 | 退款、撤销、删除并列，用户需要理解三种语义 | P1 |
| 月度分摊 | 核算完整但复杂 | 日期、费用、规则、商品输入集中在一页，首用门槛高 | P0 |
| 经营页 | 结论优先 | 现金、非采购支出、固定分摊并列时仍可能混淆“已付”与“预计成本” | P0 |
| 我的/数据管理 | 保护较强 | 备份、恢复、导入、清空均有确认，但低频高风险动作密集 | P2 |
| 自动化回归 | 核心链路已有覆盖 | 一条移动端脚本在首页/材料入口上与最新文案不同步 | P1 |

## 二、关键任务的操作负担

| 商户目标 | 当前主路径 | 主要阻力 | 简化方向 |
|---|---|---|---|
| 今天卖了一单 | 经营 → 记销售 → 选择商品 → 填数量、成交价、日期 → 保存 | 与“其他收入”入口相邻，但两者区别需用户自行判断 | 统一到“记一笔”入口，先选“卖商品/收支”，商品销售默认带出商品、价格和当天日期 |
| 今天进了一批货 | 首页条件式入口或商品成本的进阶入口 → 材料 → 金额、数量、采购/使用单位、换算、日期、是否记支出 | 材料入口不始终可见；默认名称和默认数字容易被当成已录入数据 | 提供全局“采购材料”入口；默认字段留空，仅把示例放在占位符；换算折叠为“单位不同才填写” |
| 给商品补成本 | 商品 → 录入成本 → 主成本、附加成本 → 保存 | 基础路径短，但“进阶明细”会立即切入高密度 BOM 表单 | 保留“两项快速成本”为默认；进阶页改为分步添加，损耗、出成量、版本记录放入“更多设置” |
| 算本月房租人工 | 我的 → 月度成本分摊 → 日期 → 费用项目 → 分摊规则 → 每个商品的产量/销售额/权重 → 保存 | 一页同时要求输入 7 类费用、设备、时间、规则和商品参数 | 拆为“费用总额 → 分摊依据 → 商品核对”三步；先按产量给出默认方案，其他规则与权重按需展开 |
| 查看赚没赚钱 | 首页 → 经营结果，或经营 → 图表/构成/销售记录 | 已收已付、间接分摊、资金成本在不同区域表达，用户可能当成同一口径 | 经营页先固定显示“现金”和“销售结转利润”两个切换层；预测分摊只在成本分析层出现 |
| 改错一笔销售 | 经营 → 销售记录 → 退款/撤销或删除 | “退款、撤销、删除”并列，用户难判断哪一个保留业务事实 | 用“客户退款”“录错删除”两个一级动作；全额退款自动标注为撤销，删除要求说明“录入错误” |

## 三、P0：优先修复的流程问题

### 1. 建立唯一的高频“记一笔”入口

当前收入、支出、销售、采购材料和新建商品分别由首页条件卡、经营页按钮、商品页和弹层入口承载。此设计对熟悉系统的用户可用，但对小商户意味着“我今天只是收了一笔钱，应该点哪里？”需要先理解模块结构。

建议在底部导航中增加居中的 **“记一笔”** 主动作，打开四项选择：**卖商品、记收支、采购材料、新建商品**。每一项都保留当前准确性逻辑，但由系统预填今天日期、当前行业分类和最近使用的商品/材料。首页“现在最该做”只负责引导，不再承担唯一入口职责。

**验收标准：** 新用户可在任意标签页两次点击内开始录入销售、收支、采购或商品；不必先返回首页或理解“经营/商品”模块差异。

### 2. 将材料采购从“条件出现”改为稳定入口，并清除看似数据的默认值

材料新增界面在没有上游建议时会给出“示例材料”、金额、数量、单位等默认值。即使这是表单初始值，用户也很容易把它理解为系统已经带入了一笔材料数据；此前用户对未知数据的反馈也印证了这一风险。材料入口同时依赖首页的准备度状态，导致“先采购、后建商品”的真实流程不够顺畅。

建议新增稳定的“采购材料”入口，并把材料名称、采购金额、采购数量全部改为空值；示例仅作为淡色占位符。采购单位与使用单位相同的场景默认隐藏换算系数，只有用户选择“单位不同”时再展开。是否同步记现金支出应在保存前用一句结果提示明确说明，而不是仅以开关表达。

**验收标准：** 空账本用户可以直接开始采购材料；未填写名称、金额、数量时不能保存；首次打开不显示任何看似正式账本的数字或名称。

### 3. 分离“现金发生”与“预计分摊”

经营页当前既展示已付现金，又展示非采购支出、固定分摊、资金成本。虽然每项的会计计算正确，但它们并不是同一时间属性：前两项可能是现金/流水口径，固定分摊则是用于单件成本和定价的期间归集。并列呈现会让用户误以为固定分摊也已经发生付款，或在销售未结转时把现金差额当利润。

建议将经营页拆为两个视觉层：默认的 **“现金发生”** 只保留收款、付款、本金、利息和现金结余；次级的 **“成本分析”** 再显示直接成本、月度分摊、资金成本与销售结转利润。固定分摊需明确标注“预测/分摊，不等于本期已付”。

**验收标准：** 无销售时用户只能看到现金结余，不会在默认首屏把月度分摊理解为付款；有销售后可一键查看利润由哪些快照成本构成。

### 4. 将月度分摊改成渐进式三步工作流

当前月度分摊页在一个长弹层中同时要求用户理解有效日期、整月/按天、七类费用、设备折旧、三种规则、总工时、各商品产量/销售额/权重。这对需要精细核算的商户是完整的，但不适合作为首次输入体验。

建议设计为三步：第一步“本期费用”只录房租、人工、水电和“其他”；第二步“怎么分”默认按产量，并以最近销售/库存或用户填写的总件数预填；第三步“确认商品”只显示将受影响的商品和每件分摊。设备折旧、时间比例、工时、销售额、权重移入“高级设置”。

**验收标准：** 首次用户在不填写设备、权重和工时的情况下可以完成按产量分摊；高级配置仍可完整覆盖当前三种分摊规则和时间口径。

## 四、P1：提升理解与纠错效率

| 问题 | 建议 | 不应改变的边界 |
|---|---|---|
| 商品详情操作过多 | 首屏仅保留“录入/更新成本”和“设置/查看定价”；库存、进阶明细、删除放入“更多” | 商品删除的历史销售保护必须保留 |
| 进阶 BOM 表单密度高 | 改为“添加一项成本”逐行卡片；损耗、出成量、成本归类和版本恢复默认收起 | 自定义项目的名称、单位、单价、数量校验不可删除 |
| 定价术语容易误读 | 增加“利润率（售价中的利润）/加价率（成本上的加价）”选择与一句解释 | 保本价、平台费率和成本口径公式仍需可追溯 |
| 销售纠错语义重叠 | 退款面向真实客户退款；删除面向录入错误；全额退款自动标为撤销 | 退款、删除必须回滚关联流水、成本快照与库存 |
| 期间选择重复出现 | 将当前经营月份作为全局上下文，首页/经营页只在切换时显式显示 | 所有汇总仍必须按同一业务期间计算 |
| 自动化移动端脚本部分失配 | 更新首页准备度和材料入口断言，区分“流程变化”与“真实入口不可达” | 保留现有核算、日期、销售拦截和成本快照断言 |

## 五、P2：降低维护成本与提高信任感

数据管理应将“备份与恢复”作为默认区，将导入、清空、退出登录等高风险操作收进“高级数据操作”，避免与日常备份并列。行业切换可从四张常驻卡改为一个当前行业卡加选择面板，减少设置页长度。消息中心可仅在有未读或重要公告时显示显性入口，避免低频功能占用注意力。

同时建议在所有可编辑金额字段统一采用“空值即未填写”的输入规则。当前快速成本、快速记账和最新定价输入已接近这一体验；材料、库存、旧版资金成本和部分分摊字段仍应逐步统一，避免用户把默认 0 误当为系统数据。

## 六、建议的实施顺序

| 阶段 | 主题 | 交付物 | 成功指标 |
|---|---|---|---|
| 第一阶段 | 高频录入收敛 | “记一笔”统一入口、稳定材料采购入口、材料表单留空 | 从任意页开始销售/采购/收支不超过 2 次点击 |
| 第二阶段 | 经营口径分层 | 现金发生/成本分析双层经营页、固定分摊来源标签 | 用户测试中不再把现金结余或分摊误说成利润/付款 |
| 第三阶段 | 高级能力渐进展开 | 三步月度分摊、商品更多菜单、进阶 BOM 分步输入 | 首次月度分摊完成时间显著下降，字段跳过率下降 |
| 第四阶段 | 纠错和维护 | 销售编辑/纠错语义、数据管理高级区、更新移动端回归 | 高风险操作都有明确预览、确认与测试覆盖 |

## 七、保留原则

简化不等于删除核算能力。以下能力应保留在高级层或自动化层：销售成本快照、退款回滚、业务日期、月度分摊有效日期、设备折旧、工时/销售额/产量分摊、行业模板、自定义成本项目、手动备份恢复与导出。它们是系统“算得清”的信任基础；下一轮改造只应减少用户第一次看见它们的频率，并在需要时提供清晰解释。

## 八、审计依据

本报告基于当前项目的真实前端路径、数据模型、组件测试和 390×844 移动端回归进行审阅。重点审阅范围包括 `OnboardingFlow.tsx`、`QuickRecordSheet.tsx`、`QuickCostSheet.tsx`、`BomEditorSheet.tsx`、`MonthlyCostSheets.tsx` 与 `Home.tsx`；移动端回归确认了首次建账、快速记账、商品成本、定价与销售日期的主要链路。当前回归中首页准备度和材料新增入口的断言未与最新入口文案/条件同步，已列为 P1 测试维护项。
