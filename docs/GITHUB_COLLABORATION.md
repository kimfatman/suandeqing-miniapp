# GitHub 协作说明

## 推荐仓库设置

仓库建议使用 `main` 作为稳定分支。首次推送前需确认仓库归属（个人或组织）、可见性（私有或公开）以及是否已存在同名仓库。若仓库已有内容，应先确认是否允许合并，避免覆盖对方历史。

## 分支与提交

| 场景 | 建议 |
|---|---|
| 小型修复 | 从 `main` 创建 `fix/简短主题`，提交后经 PR 合并 |
| 新功能 | 从 `main` 创建 `feat/简短主题`，保持一项功能一组可回归提交 |
| 视觉改造 | 使用 `design/简短主题`，附移动端截图和回归说明 |
| 紧急修复 | 使用 `hotfix/简短主题`，记录问题、影响与验证结果 |

提交消息建议采用中文动词开头，例如：`feat: 增加商品成本分析驾驶舱`、`fix: 修正退款后的库存回滚`、`docs: 补充核算口径说明`。

## Pull Request 检查清单

1. 说明用户可见变化与不变的核算边界。
2. 列出 `pnpm test`、`pnpm build` 和移动端验证结果。
3. 涉及账本结构或销售逻辑时，列出历史数据兼容与回滚方案。
4. 涉及 UI 时，说明 375、390、414 宽度检查结果。
5. 不在 PR 描述、截图、日志或代码中包含密钥、令牌、Cookie、账本导出或用户个人数据。

## 安全规则

- 不提交 `.env`、真实 OAuth/数据库/API 密钥、浏览器会话、生产导出数据或下载文件。
- 使用 GitHub 的仓库 Secrets 或受控平台密钥管理，而不是在源码中写入配置值。
- 用户账本属于敏感经营数据；用于复现问题时应先脱敏，并避免将真实销售、采购、人员或债务信息上传。
- 公开仓库前应再次检查提交历史和分支，必要时旋转已泄露的凭据。

## 首次推送验收

首次上传后应在 GitHub 检查：默认分支、README 渲染、文档链接、`.gitignore`、提交记录和仓库可见性。随后可启用分支保护、PR 审核和自动化测试工作流。
