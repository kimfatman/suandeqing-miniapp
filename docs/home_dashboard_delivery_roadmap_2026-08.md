# 「算得清」经营驾驶舱开发排期与里程碑

## 1. 规划口径与当前基线

本排期以 **2026 年 8 月 20 日启动、单一全栈开发主线、每周 5 个工作日**估算，总周期为 **6 周**。排期把已发布的现金收付动态图表、销售快照利润桥、单件成本构成与商品直接贡献图作为基线，不重复开发。后续所有工作都以真实账本、销售成本快照、退款回滚和业务日期为约束；缺少数据时展示数据不足，不向正式账本写入演示或 Mock 数据。

| 已具备能力 | 后续可直接复用 |
|---|---|
| 现金与利润分层 | 经营结果卡、趋势图与行动建议可分别引用实际收付款和销售结转数据 |
| 销售成本快照与退款回滚 | 商品盈利/亏损、趋势和异常计算可按业务日期复算 |
| 月度间接成本计划 | 完整成本、定价建议和分摊异常可使用现有计划，但不能当成实际现金 |
| 品牌化组件与移动端框架 | 首页驾驶舱可复用账页、账签、卡片、图表、底部导航和可访问性规范 |

## 2. 总体里程碑

| 里程碑 | 时间 | 发布目标 | 可验证业务结果 |
|---|---:|---|---|
| M0：驾驶舱范围冻结 | 第 1 周前半段 | 数据字典、阈值和首页信息架构确认 | 确认哪些是实际、已结转、预计数据，避免后续口径返工 |
| M1：首页驾驶舱 MVP | 第 1 周后半段至第 2 周 | 经营结果、紧凑现金情况、现有图表与 Top 5 商品进入首页 | 用户 5–15 秒内看到本期结果、趋势与商品表现 |
| M2：趋势与日期明细 | 第 3 周 | 7 天/30 天/本月/近 3 个月，收入/成本/利润切换 | 用户点按数据点能看到对应日期的同口径明细 |
| M3：商品盈利与异常引擎 | 第 4 周 | 商品完整贡献、异常中心、行动建议 | 用户可找到低毛利/亏损/低于建议售价的商品并直达处理入口 |
| M4：经营建议与跨期比较 | 第 5 周 | 最多 3 条决策提醒、真实环比和趋势判断 | 用户可理解原因、影响和下一步动作；无历史时明确数据不足 |
| M5：数据基础与发布硬化 | 第 6 周 | 采购价格历史、库存阈值/应收能力的最小数据方案；全量验收 | 为 P2 预警准备可靠数据，并完成稳定版发布 |

## 3. 分阶段工作包

### M0：驾驶舱范围冻结（第 1 周，2 个工作日）

本阶段不大改 UI，先冻结计算与展示规则。需要建立统一的首页视图模型，明确“现金发生”“已结转利润”“预计分摊”三个来源字段，所有首页组件只读这一视图模型。与此同时，确定低毛利、亏损、成本上涨和收入下降的默认阈值，并把阈值设计为可配置常量，而不是散落在组件内。

| 工作项 | 依赖 | 验收标准 |
|---|---|---|
| 编制首页指标字典与数据来源表 | 现有 `summarizeLedger`、销售快照 | 每个首页金额可追溯到现金流水、销售快照或分摊计划之一 |
| 冻结异常规则与阈值 | 商户业务确认 | 低毛利、亏损、成本上涨、收入下降均有明确公式和无数据行为 |
| 输出首页信息架构线框 | 品牌化 UI 规范 | 顺序固定为结果→趋势→商品→异常→行动建议 |

> **M0 决策闸门：** 确认低毛利阈值、异常提示是否默认启用、商品排行先显示“直接贡献”还是“完整经营利润”。未确认前，不把阈值写死为用户可见结论。

### M1：首页驾驶舱 MVP（第 1 周后半段至第 2 周，8 个工作日）

本阶段把已经验证过的动态能力整合到首页，而非再次开发图表库。首页顶部变为紧凑经营结果卡，显示盈利、亏损或待销售结转；现金情况作为辅助信息。随后放置已有经营趋势、商品贡献 Top 5、首批异常和行动建议。所有入口直接跳转到既有经营、商品、定价或成本录入流程。

| 工作项 | 产出 | 验收标准 |
|---|---|---|
| 结果卡重构 | 三状态经营结果卡 + 紧凑现金辅助卡 | 无销售时不显示伪利润；亏损有明确负向状态；金额与经营页一致 |
| 图表迁移与首页适配 | 经营趋势入口与动态图表摘要 | 390×844 触控选择可用；无数据状态有下一步动作 |
| 商品赚钱能力 Top 5 | 当前期间商品贡献列表、风险标记、商品跳转 | 数据来自销售快照；商品不足 5 个时不填充假数据 |
| 首批异常与建议 | 低毛利/亏损/未定价/待补成本的任务卡 | 每项有原因、影响或风险说明、可执行入口 |

**M1 发布验收：** 在正式空账本、仅现金、有效销售、退款、亏损五种场景下，首页均能在首屏给出正确结论；全量单元测试、390×844 回归、桌面截图和生产构建通过。

### M2：趋势与日期明细（第 3 周，5 个工作日）

本阶段补齐经营趋势应有的时间维度。需要新增可复用的日粒度、月粒度聚合器，并以业务日期处理补录与退款。图表支持 7 天、30 天、本月、近 3 个月及收入/成本/利润切换；点按数据点打开同日期经营明细，不直接跳入编辑态。

| 工作项 | 数据要求 | 验收标准 |
|---|---|---|
| 时间范围聚合器 | 流水、销售、退款按业务日期聚合 | 补录、跨月退款、无数据范围不会错误归集 |
| 多指标趋势 | 收入、成本、利润独立序列 | 现金付款不进入利润序列；预计分摊有明确标签 |
| 日期经营明细 | 只读日期抽屉/弹层 | 能解释当天收入、成本、退款和净结果的来源 |
| 趋势判断 | 增长、下降、连续变化、数据不足 | 只在比较基数有效时生成判断；否则展示数据不足 |

### M3：商品盈利与异常引擎（第 4 周，5 个工作日）

本阶段将商品“直接贡献”提升为可解释的商品经营表现。优先使用销售时冻结的直接、间接和资金成本；若历史销售缺少某类快照，则逐行降级标记，不能混合为精确完整利润。异常中心开始提供成本上涨、低毛利、亏损和售价偏低等规则，并让每个异常直达对应商品、成本或定价动作。

| 工作项 | 依赖 | 验收标准 |
|---|---|---|
| 商品完整贡献聚合 | 销售成本快照完整性 | 排行总额可与期间销售汇总对账；退款按原快照冲减 |
| 商品风险标签 | M0 阈值 | 明确“低毛利”“亏损”“数据不完整”的区别 |
| 异常中心 | 商品与期间聚合 | 显示问题数；每条可进入原因说明和处理入口 |
| 定价联动 | 既有 PricingPanel | 建议售价仍可复算，并明确预计分摊与已实现利润的差异 |

### M4：经营建议与跨期比较（第 5 周，5 个工作日）

本阶段将异常转为最多 3 条行动建议。建议必须由规则模板生成，而不是不可审计的自由文本；每条应显示原因、经营影响和动作。环比仅在上一可比业务期间完整且同口径时展示。

| 工作项 | 验收标准 |
|---|---|
| 建议规则模板 | 每条建议可追溯到具体指标与阈值，最多 3 条且按影响排序 |
| 环比与趋势基数 | 跨期缺失、开店首月、退款跨月均有明确降级说明 |
| 影响量计算 | 仅在输入齐全时展示“少赚/可改善”金额；否则不虚构金额 |
| 首页行动闭环 | 点击建议可直达商品、定价、成本或经营明细，完成后状态刷新 |

### M5：数据基础与发布硬化（第 6 周，5 个工作日）

本阶段为 P2 预警补齐最小数据能力，并完成上线前硬化。优先设计材料采购价格历史、库存阈值和应收账款的数据模型与迁移方案；如果模型尚未达到可审计标准，则只发布数据采集入口，不展示“库存健康”或“待收款过高”结论。

| 工作项 | 验收标准 |
|---|---|
| 采购价格历史 | 每次采购保留材料、单位、换算、金额、数量与业务日期，可生成真实价格趋势 |
| 库存阈值 | 仅对已启用库存的商品展示低库存提醒；不虚构库存 |
| 应收能力评估 | 未有应收模型时明确延期；若实现则应收与实际收款必须分开 |
| 发布硬化 | 全量账务回归、极端数据、辅助功能、移动端/桌面端、性能与可访问性通过 |

## 4. 关键依赖与风险控制

| 依赖或风险 | 影响 | 控制方案 |
|---|---|---|
| 历史销售的成本快照不全 | 无法可靠计算商品完整利润 | 分层标记“直接贡献/完整利润”，不混算、不伪造 |
| 缺少跨期数据 | 环比和近 3 个月判断不可靠 | 显示数据不足，关闭百分比与趋势结论 |
| 退款跨月 | 销售、成本和利润可能归期错误 | 所有聚合按退款业务日期和原销售快照处理，并以回归测试保护 |
| 分摊是预计数据 | 容易被误读为实际费用或利润 | 在图表、异常和定价中明确“预计分摊”；不得混入现金图 |
| P2 数据模型缺失 | 库存/应收/采购价趋势会变成猜测 | 先建数据采集和迁移，再发布预警结论 |
| UI 信息过载 | 首页从驾驶舱退化为报表页 | 每个模块最多一个主结论、一个可解释图表、一个行动入口 |

## 5. 发布节奏与质量闸门

建议每个里程碑结束时生成一个可回滚发布版本，而不是等 6 周后一次性上线。M1、M2、M3 和 M5 是功能发布节点；M0 与 M4 可作为内部规则确认节点。每个发布节点必须通过 TypeScript、Vitest、生产构建、390×844 移动端关键路径、桌面视觉复核，并新增与本阶段对应的账务口径断言。

| 节点 | 发布条件 | 禁止发布条件 |
|---|---|---|
| M1 | 首页结果、现金、商品贡献与任务卡均有真实数据/空状态 | 现金显示为利润，或 Top 5 使用演示商品补位 |
| M2 | 每种时间范围和指标均可追溯到业务日期 | 跨月退款被计入原销售日或图表无法解释来源 |
| M3 | 商品排行与期间汇总可对账，异常可直达处理 | 缺失快照仍显示“完整利润” |
| M4 | 建议可解释、可行动、可降级 | 通过模糊 AI 文本或无数据金额诱导用户决策 |
| M5 | P2 数据模型、迁移、删除/导入导出与全量回归完备 | 只凭当前余额推断库存、应收或采购价格趋势 |

## 6. 需要产品确认的四项决策

在 M0 前确认以下事项，可避免排期后半段返工：第一，低毛利的默认阈值是否采用统一值，还是按行业模板区分；第二，商品排行首先显示完整经营利润还是数据更完整的直接贡献；第三，跨期比较以自然月、近 30 天还是商户自定义账期为主；第四，M5 是否进入采购历史、库存阈值与应收账款的数据模型扩展，还是先收敛到首页驾驶舱一期。
