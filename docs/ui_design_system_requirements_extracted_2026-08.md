# “算得清”UI Design System 需求提炼

> **来源**：用户上传的《pasted_content_2.txt》。本文将通用的 8px Grid、按钮令牌和视觉比例规则，转化为适用于“算得清”现有品牌化账页界面的可执行规范；本轮仅提炼需求，不直接替换页面样式。

## 1. 产品目标与实施原则

“算得清”应从“单页看起来整洁”升级为**跨首页、商品、经营、我的与所有弹层都由同一设计系统驱动**的产品。任何页面改造都必须优先调用已定义的间距、尺寸、圆角、字体、图标与状态令牌；发现比例问题时，优先修正组件令牌，而不是给单一页面增加一次性 CSS 数值。

现有“账页、账签、算清蓝、深墨、加号/等号/微笑曲线”仍是品牌资产，不应被通用组件规范抹平。品牌化账页容器可使用**已命名的账页组合圆角**，但其每个值必须来自统一圆角令牌，不能继续自由组合随机数值。

## 2. 必须建立的设计令牌

### 2.1 间距与布局

| 类别 | 允许值 | 使用规则 |
|---|---:|---|
| 基础间距 | 4、8、12、16、20、24、32、40、48、64 px | 默认以 8px Grid 为主；4/12/20 仅用于紧凑控件内部、图标间距或小屏微调。 |
| 页面左右边距 | 16 或 24 px | 同一断点内保持一致；移动端默认 16px，宽屏可升至 24px。 |
| 卡片间距 | 8、16 或 24 px | 同一信息层级不可混用近似随机间距。 |
| 区块间距 | 24、32 或 40 px | 首页大区块、表单段落和弹层分段遵循该级别。 |
| 图标与文字 | 8 px | 所有“图标 + 文字”按钮、行动项与标签遵循统一间距。 |

### 2.2 按钮与触控规格

| 令牌 | 高度 | 字号 | 横向内边距 | 圆角 | 图标 | 适用范围 |
|---|---:|---:|---:|---:|---:|---|
| `button-lg` | 48 px | 16 px | 20 px | 10 px | 18 px | 核心 CTA、表单提交、关键经营动作。 |
| `button-md` | 40 px | 14 px | 16 px | 8 px | 16 px | 默认页面主操作与弹层确认操作。 |
| `button-sm` | 32 px | 13 px | 12 px | 6 px | 14 px | 卡片内次级操作、筛选与轻量表格操作。 |
| `button-text` | 32 px | 14 px | 0–8 px | 6 px | 14–16 px | 链接式次级动作；不得与主按钮竞争。 |
| `icon-32/36/40` | 32/36/40 px | — | — | 8 px 或 50% | 14/16/20 px | 图标触发器；实际可点击区域最小 44×44 px。 |

每个主要区域最多出现一个 Primary Button。按钮默认内容自适应，但同组同层级按钮必须保持同一规格；较短的“删除”不能与较长的“查看完整经营分析”在同一层级呈现明显失衡的视觉重量。若确需等宽，使用明确的 `min-width: 88px` 或按钮组规则。

所有按钮必须包含 Default、Hover、Active、Focus、Disabled、Loading、Success、Error 的状态策略。Loading 状态不得改变按钮的高度或造成布局跳动；移动端所有主要操作的**实际热区**至少为 44×44 px，即使视觉本体为 32px。

### 2.3 圆角、字体和图标

| 类别 | 规范 | 备注 |
|---|---|---|
| 圆角 | 4、6、8、10、12、16 px；Pill 为 9999px | 账页容器可使用如 `16/16/12/12` 的已命名组合，不得使用临时 18/22/13 等数值。 |
| 页面标题 | 24 px（紧凑页可 20 px） | 保持经营驾驶舱的结论优先层级。 |
| 区块标题 | 20 px | 不与金额卡数字竞争。 |
| 卡片标题 | 16 px | 商品、经营异常、数据管理等复用。 |
| 正文 / 次级 / 注释 | 14 / 13 / 12 px | 避免 9–11px 成为主要可读信息。 |
| 金额重点 | 32–40 px | 仅用于首页经营结论等极少数核心财务数值。 |
| 图标 | 14、16、20、24 px | 继续统一使用 Lucide 线性图标；不使用 emoji 或混杂风格 SVG。 |

## 3. 对现有界面的适配结论

现有版本已经具备部分可复用基础：全局 `focus-visible`、160ms 交互过渡、算清蓝/深墨/薄荷绿品牌色、账页表面和品牌图形语汇均可保留。当前主要缺口在于尺寸体系尚未令牌化：样式中仍混有 37px、38px 图标按钮，13px、17px、18px、22px 等自由间距，以及 18/22/13 等未命名的圆角组合；这些需要在后续页面迭代中收敛。

| 项目 | 现状 | 需求决策 |
|---|---|---|
| 账页与账签品牌语言 | 已形成品牌辨识度 | **保留**，改为 `surface-ledger`、`radius-ledger` 等显式令牌。 |
| 按钮尺寸 | 存在图标按钮 37/38px 等非标准尺寸 | **P0 统一**为 32/36/40px 视觉规格和 44px 热区。 |
| 卡片圆角 | 存在多组不规则组合值 | **P0 建立**基础圆角和账页例外令牌；禁止页面临时新增。 |
| 字体层级 | 标题、说明和微标签使用值较散 | **P1 收敛**为 24/20/16/14/13/12 与 32–40px 金额体系。 |
| 间距 | 账页视觉有价值，但数值分散 | **P0 建立**8px Grid；P1 按核心路径逐页替换。 |
| 主次操作比例 | 部分文字按钮、箭头按钮与卡片动作接近 | **P1 审计**每区仅一个 Primary，箭头合入动作文本或降为 Tertiary。 |
| 无障碍和状态 | 已具备焦点/按压基础 | **P1 补齐**禁用、加载、成功、错误与触控热区验收。 |

## 4. 组件行为约束

按钮内部必须使用水平与垂直居中布局，图标与文字间距为 8px，图标尺寸不得大幅超过文字视觉高度。中文文案默认 `white-space: nowrap`；若可能超出容器，优先选择明确的文案截断、按钮组换行或独立行布局，而不是让按钮自行改变高度、压缩字体或挤压相邻元素。

卡片、列表和图表都必须遵循同一层级比例。普通卡片内按钮视觉高度通常不超过卡片高度约 30%；核心 CTA 可以更明显，但同一区域仍不得出现两个等权重主按钮。图表的高度、控件密度和说明文字应由图表组件令牌控制，不能按页面任意增减。

## 5. 页面完成后的强制审查清单

| 审查维度 | 必须验证的项目 |
|---|---|
| Button | 同层级高度、字号、圆角、图标尺寸、8px 图文间距、内边距和状态一致；Primary 不超过每个主要区块 1 个。 |
| Layout | 页面左右边距、卡片/区块间距、Grid 对齐与内容垂直对齐均来自令牌；不出现临时随机间距。 |
| Typography | 标题层级、正文/注释比例、金额强调和中英文数字基线一致；不以压缩小字解决空间问题。 |
| Touch | 主要可点击元素最小 44×44px；相邻操作留出足够间距；键盘焦点清晰。 |
| Ratio | 隐藏文字后只看卡片、按钮、图标、留白和图表，仍应保持均衡；没有“巨大按钮配小卡片”或“巨大卡片配微小按钮”。 |
| Responsive | 390×844 与桌面断点下，长按钮文案不溢出、不变高、不挤压；图表与底部操作可触达。 |

## 6. 分阶段实施优先级

| 阶段 | 工作包 | 交付与验收 |
|---|---|---|
| P0：令牌基础 | 在全局样式建立 spacing、button、icon、radius、typography、surface、state 令牌；定义账页例外令牌。 | 新建组件不得出现未登记尺寸；核心按钮/图标按钮可由令牌渲染。 |
| P1：核心路径迁移 | 优先改造首页驾驶舱、统一“记一笔”、商品成本、销售、月度分摊和数据管理弹层。 | 390×844 视觉回归；核心区块 Primary 数量、触控热区和长文案测试通过。 |
| P2：全量治理 | 清理历史随机值，建立组件目录/使用示例，并将视觉比例审查加入每次 UI 交付流程。 | 页面级一致性审计清单全部通过；不再新增一次性尺寸。 |

## 7. 明确的防回退规则

> **任何新尺寸先问“是否已有令牌”，而不是先写 CSS。** 如确实需要新增尺寸，必须先加入 Design System、说明适用范围，并在后续组件中复用；禁止仅为单个页面写一次性尺寸。

在实施时，设计系统必须服从“算得清”的业务边界：按钮和卡片的统一不能削弱“现金不等于利润”“销售快照不可改写”“预计分摊不可伪装成实际成本”等会计口径提示。视觉简化只能减少噪音，不能隐藏核算来源、纠错入口或高风险确认。
