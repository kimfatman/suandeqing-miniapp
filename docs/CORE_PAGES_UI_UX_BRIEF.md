## 目标与边界

本轮只重构**商品、经营、我的**三页的信息架构、视觉层级和移动端交互。不得改变账本数据结构、API、业务流程、销售快照、退款冲销、现金与利润的核算边界；不得虚构会员、订阅、商品或经营数据；不得删除已有真实功能入口。

## 共用视觉规则

以现代移动端商业工具为方向：核心数字、页面标题和主操作为一级信息；商品/成本/趋势为二级信息；说明、状态和辅助信息为三级信息。优先留白与细分割线，避免每个元素都使用描边卡片。品牌蓝仅用于核心 CTA 和关键数据；正向数据使用绿色，风险使用橙红色。圆角按页面容器、一级卡片、按钮、标签分层使用。字号目标为核心数字 28–32px、页面标题 24–28px、模块标题 18–20px、核心数据 16–18px、正文 14px、辅助文字 12px。

“+ / =” 是克制使用的品牌语言：新增、记一笔、成本计算和利润结果可见，但不能成为无意义装饰。底部导航必须保留“首页｜商品｜记一笔｜经营｜我的”信息架构，中间加号明确表达“记一笔”。

## 商品页验收方向

顶部为“商品 / 管理商品成本，掌握每一份利润”及“+ 新增商品”。列表中的金额必须标注含义，至少可识别售价、单件成本、单件利润与毛利率。选中商品详情需在同一口径下展示售价、成本、利润、毛利率与成本结构。原有成本分析、直接成本/更新成本、定价与更多操作均须保留，但收敛为轻量快捷入口；成本分析为主入口。

## 经营页验收方向

顶部突出本期经营利润、利润率、销售收入、商品成本与经营费用，并清晰表明“现金流不等于经营利润”。使用“现金流｜利润分析”分段控件，替换偏财务化的“现金发生”。现金流层显示真实收入、支出、净现金流和真实空状态；利润分析层显示销售收入减销售快照成本、经营费用后得出经营利润。现金明细保留“查看全部”，底部保留显性的收入、支出记录入口。

## 我的页验收方向

顶部显示真实店铺资料和可进入的数据/账户入口；不可虚构会员状态。将行业、成本项目、分摊规则、资金成本组织为经营管理模块；成本报表、商品管理、数据备份、导出数据组织为数据管理模块；账本、账号安全、帮助与反馈、关于归为系统设置。功能状态必须来自现有账本或认证状态。

## 数据一致性验收

相同商品的售价、成本、利润与毛利率必须在商品列表、商品详情、成本分析及相关经营模块中来自一致口径。已结转利润只能来自销售快照；现金流只来自实际收付款；预计分摊不得伪装为已发生经营结果。

## 390px 视觉回归记录

- 商品页：首屏按“标题与新增 → 商品列表 → 单件成本/利润详情”展示；列表和详情中的金额均有清晰标签，页面无横向溢出。
- 经营页：首屏按“经营标题 → 本期经营利润主卡 → 现金流/利润分析分段”展示；利润卡明确标注销售快照来源，页面无横向溢出。
