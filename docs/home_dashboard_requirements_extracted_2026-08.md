# 「算得清」经营驾驶舱首页需求提取

## 1. 目标与产品定位

首页需要从“财务数据展示页”升级为**小微商家的经营驾驶舱**。其核心任务不是罗列流水，而是让商户迅速判断本期是否赚钱、趋势是否改善、哪些商品贡献利润、哪些问题值得优先处理，以及下一步应采取什么行动。

> 目标体验：**算得清 → 看得懂 → 找到问题 → 给出行动建议。**

| 时间目标 | 用户应获得的结论 |
|---|---|
| 5 秒 | 本期经营是否盈利，或为何暂不能判断利润 |
| 10 秒 | 收入、成本、利润的走势是否向好 |
| 15 秒 | 最赚钱商品与风险商品分别是谁 |
| 20 秒 | 当前最应该处理的经营动作 |

## 2. 首页信息架构

页面阅读顺序应固定为：**经营结果 → 经营趋势 → 商品赚钱能力 → 经营异常 → 今天值得关注**。现金情况可以作为紧凑的辅助指标，但不得替代或混淆经营利润。

| 模块 | 核心问题 | 展示目标 |
|---|---|---|
| 本月经营结果 | 这个月赚了还是亏了？ | 显示经营结果、销售收入、成本、毛利率与环比；无有效销售结转时明确显示“利润待销售结转” |
| 经营趋势 | 收入、成本、利润如何变化？ | 支持时间和指标切换的交互折线图，并给出一句基于数据的经营判断 |
| 商品赚钱能力 | 哪些商品真正赚钱？ | 展示 Top 5，包含销售额、成本、毛利、毛利率和横向贡献条 |
| 经营异常 | 哪些问题正在影响利润？ | 汇总问题数，并提供原因、影响、建议售价或下一步处理入口 |
| 今天值得关注 | 我现在应该做什么？ | 最多 3 条“原因 → 影响 → 建议动作”的决策提醒，而不是聊天机器人 |

## 3. 详细功能需求

### 3.1 经营结果卡

经营结果卡应减少高度与装饰，让金额成为视觉重点。卡片需要区分盈利、亏损和“尚不能判断利润”三种状态。盈利与亏损使用明确状态色；当没有有效销售结转时，只显示现金相关指标与“尚待销售结转”的说明，不得将现金余额写成经营利润。

| 字段 | 要求 | 数据边界 |
|---|---|---|
| 本期经营结果 | 正数、负数或待结转状态 | 使用销售收入减销货成本、间接分摊与资金成本 |
| 收入、成本、毛利率 | 并列的紧凑指标 | 来自本期销售快照，不混入单纯现金付款 |
| 较上期变化 | 有足够可比历史时展示 | 仅比较同口径的完整业务期间；没有数据时不伪造百分比 |
| 现金情况 | 单独辅助卡 | 显示实际收付款与现金余额，不宣称为利润 |

### 3.2 经营趋势动态图表

图表默认使用最近 30 天，并提供**7 天、30 天、本月、近 3 个月**的时间切换；提供**收入、成本、利润**指标切换。每个数据点必须可在桌面端悬停、移动端点按，显示日期与对应金额；点按后应进入或打开该日期的经营明细。

图表采用响应式、低对比网格线和克制的折线样式，不使用 3D、厚重渐变填充或传统 Excel 式装饰。图表下方需要根据真实数据生成一句判断，例如增长、连续下降或数据不足。若选择的范围没有真实数据，显示空状态和明确的下一步记录动作。

### 3.3 商品赚钱能力

模块应展示本期 Top 5 商品，默认按**已实现利润或可解释的利润贡献**排序，而非单纯按售价。每个商品至少显示销售额、销售成本、毛利、毛利率和水平条。低毛利或亏损商品应有风险标记；点按商品可进入对应商品成本分析/定价页面。

实现时应优先使用销售时冻结的直接成本、间接成本和资金成本快照。若当前只能可靠得到直接贡献，应在界面明确标记“已结转直接成本贡献”，不要将其误称为完整经营利润。

### 3.4 经营异常

异常模块需要展示“待处理问题数”，并至少支持以下规则：低毛利、商品亏损、成本上涨、售价低于合理建议、收入下降、固定成本异常、单品利润下降。待收款仅在账本具备真实应收数据后启用。

每项异常应包含：**原因、影响、建议动作**。例如，低毛利商品应能展示当前售价、可复算成本、建议售价区间，以及进入定价或成本明细的入口。

### 3.5 今天值得关注

系统基于真实本期数据最多生成 3 条提醒。每条内容采用“原因 → 经营影响 → 建议动作”的结构，并提供合理跳转，例如去调整售价、查看成本分析、记录销售或补齐成本。该区域不应模拟聊天，不应以无数据推测商户经营状况。

## 4. 视觉与交互要求

整体风格是现代、专业、克制、数据驱动，面向老板而不是财务人员。使用专业蓝作为主操作色，绿色表示盈利或正向结果，橙色表示风险，红色表示亏损；保持现有深墨文字、浅色账页与白色卡片体系，避免高饱和色堆叠、紫色大渐变、过度圆角卡片和夸张动画。

移动端采用单列优先的阅读顺序；平板与桌面端可调整为多列，但不得把移动页面简单放大。所有图表必须有点按替代悬停、明确空状态、加载状态、错误状态、利润/亏损状态和极端数值状态。动画仅用于数值加载、图表进入、标签切换和轻微风险强调，并尊重“减少动画”偏好。

## 5. 数据与业务保护约束

本任务是首页 UI/UX 重构，必须保留现有 API、账本数据结构、销售成本快照、退款回滚、业务日期和成本核算逻辑。图表优先使用真实账本数据；不得向正式账本写入 Mock/演示数据。缺少历史数据时显示“数据不足”或空状态，而不是虚构环比、趋势、商品利润或经营建议。

现金、利润和预计分摊必须分层表达：实际收付款用于现金图；销售结转快照用于利润图；月度分摊计划用于定价/预计成本图，并明确其不是已发生现金或已实现利润。

## 6. 建议实施优先级

| 优先级 | 需求 | 前置条件 |
|---|---|---|
| P0 | 首页经营结果卡收敛、现金/利润口径分层、现有动态图表接入首页 | 现有汇总与销售快照已具备 |
| P0 | 商品贡献 Top 5、低毛利/亏损异常、行动建议 | 需按商品聚合当前业务期间的销售成本快照 |
| P1 | 趋势时间与指标切换、按日期经营明细、环比判断 | 需补足可选择的日/月聚合与可比期间判定 |
| P1 | 建议售价区间、成本上涨、单品利润下降等异常规则 | 需定义异常阈值与历史比较基准 |
| P2 | 待收款、库存健康、材料采购价趋势 | 当前账本需先建立应收、库存阈值和采购历史数据模型 |

## 7. 验收标准

重构完成后，应验证首页可在无销售、盈利、亏损、退款、跨月、极端金额和无历史数据场景下正确工作。验收需覆盖：视觉一致性、图表触控/悬停、时间与指标切换、空/加载/错误状态、桌面/平板/390×844 移动端布局，以及所有图表与销售快照、现金流水和月度分摊口径的一致性。
