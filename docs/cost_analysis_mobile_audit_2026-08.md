# 成本分析移动端 UI 审计

## 390×844 首屏

成本分析已从商品详情的“成本分析”入口进入，顶部商品切换器保留具体商品上下文。首屏遵循“现在赚多少 → 钱都花在哪里 → 成本异常”顺序；蓝色核心卡使用“售价 − 单位完整成本 ＝ 单位毛利”和毛利率，成本结构以环形比例和横向明细展示。异常提示使用局部浅色状态，不将高成本或亏损渲染为整块红色。

## 390×844 下半屏

趋势明确标注为“已结转单位直接成本”，不会将当前成本倒灌到历史销售。盈亏模拟明确标为预计测算，调整售价、成本和销量仅更新临时结果；保本售价使用当前单位完整成本，和销售快照利润保持分离。所有模拟增减与底部动作均使用44px以上触控区域。

## 后续检查

发布前仍需复核建议区、无成本/无售价/亏损状态，以及375、414宽度下的商品选择、计算式、成本明细、模拟输入和底部操作比例。

## 375 / 414 宽度审计

375 宽度下，商品切换、三段盈亏计算式、成本环图与成本明细可同时完整显示；414 宽度下，卡片内部留白和数字比例保持稳定。两种宽度均未出现横向滚动、按钮挤压或底部中心记一笔覆盖内容的问题。真实账本回归同时验证了商品绑定与模拟售价的实时更新。

建议区复核确认：保本价、当前售价和安全空间以价格区间呈现；建议不伪装为聊天内容，而是提供到成本和定价的具体行动。底部“调整售价 / 添加成本”均满足主次层级与触控比例，不遮挡底部导航。
