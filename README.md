# 算得清

> 面向中国中小商家和小商贩的移动端成本核算与经营决策工具。

“算得清”帮助商家把**材料采购、商品成本、销售结转、月度间接费用、资金成本与定价**放进同一套可追溯口径中。产品并不把现金收付直接当作利润；只有商品销售完成收入与成本结转后，才展示经营结果。

## 产品能力

| 模块 | 已实现能力 | 关键边界 |
|---|---|---|
| 首页经营驾驶舱 | 经营结果、现金、趋势、商品贡献、异常与快捷操作 | 现金、销售快照利润、预计分摊分别说明 |
| 商品与成本 | 行业模板、快速成本、BOM版本、材料采购、库存与安全删除 | 历史销售使用冻结成本，不被后续材料价格改写 |
| 销售与纠错 | 销售结转、部分退款、全额撤销、录错删除 | 退款和删除会同步更正收入、成本与库存 |
| 月度间接成本 | 房租、人工、水电、折旧等费用，按产量/工时/销售额分摊 | 支持有效日期、按天折算与商品权重 |
| 定价与成本分析 | 建议价格、完整成本明细、保本线、模拟与行动建议 | 当前预计、模拟结果与已结转销售快照明确区分 |
| 数据与账号 | 本机账本、导入导出、云端备份、Manus OAuth、站内消息 | 登录退出不删除本机账本；首期不自动合并 |

## 快速开始

### 前置条件

- Node.js 22 或兼容运行环境。
- pnpm 10。
- 已配置项目模板提供的数据库与 OAuth 环境变量；不得将真实密钥提交到仓库。

### 安装与运行

```bash
pnpm install --frozen-lockfile
pnpm dev
```

开发服务由 Express 与 Vite 桥接启动。生产构建与本地测试分别使用：

```bash
pnpm test
pnpm build
pnpm start
```

## 核算原则

1. **现金不等于利润。** 现金卡只统计实际收付款；商品利润只来自销售结转。
2. **历史不漂移。** 销售时冻结直接成本、间接分摊和资金成本快照，后续修改成本不改写历史结果。
3. **预计不冒充已发生。** 当前商品完整成本、月度分摊、定价和模拟均标示为预计或当前口径。
4. **退款与删除语义不同。** 客户退款保留真实业务事实；录错删除移除错误录入及关联结转。
5. **无来源不展示。** 不构造虚假环比、行业均值、待收款或用户评价数据。
